## 3. 需求页（D12）

```
┌────────────────────────────┐
│ [搜索栏] 搜索标题、科室、医院… │  搜索：标题/科室/医院名模糊
├────────────────────────────┤
│ 综合▾ 类型▾ 科室▾ 时间▾ 价格▾ ⋁│  筛选导航栏（吸顶）
│ (已选条件胶囊回显区，可单个清除) │
├────────────────────────────┤
│ [广告位1] 需求流第2条 · 地域定向│
│ ┌────────────────────────┐ │
│ │[值班]  求值8/28夜班… 待接单│ │  需求卡片
│ │吉大一院 · 8/28 18:00-次日8:00│ │  类目标签+状态右上角
│ │￥200                     │ │  价格暖褐强调
│ └────────────────────────┘ │
└────────────────────────────┘
```

**筛选器规格：**

| 筛选维度 | 控件 | 选项 |
|---|---|---|
| 综合（排序） | 下拉单选 | 最新发布 / 价格从低到高 / 价格从高到低 / 时间临近 |
| 类型 | 下拉单选 | 全部 / 值班 / 病例指导 |
| 科室 | 下拉单选（标准科室字典） | 全部 + 一级科室 + 亚专科 |
| 时间 | 下拉单选 | 全部 / 近24小时 / 近7天 / 近30天 / 自定义起止 |
| 价格 | 下拉单选 | 全部 / 面议 / ￥0-100 / 100-300 / 300+ / 自定义区间 |
| ⋁ 筛选抽屉 | 半屏抽屉 | 医院搜索（**模糊+别名匹配**）、省市级联、价格区间输入 |

服务端对应 `dealing.list` 参数：`keyword, sort, category, department, timeFrom, timeTo, feeMin, feeMax, hospitalId, province, city`。

```
┌────────────────────────────┐
│ [话题：全部▾] [时间：近7天▾]   │  筛选胶囊行
│ [省市：长春市▾（跟随浏览地域）]  │
├────────────────────────────┤
│ ┌────────────────────────┐ │
│ │(李) 李医生·吉大一院  1小时前 │ │  帖子：头像+昵称+医院
│ │#规培心得#                │ │  话题标签
│ │第一个月夜班的三个教训…      │ │  正文两行截断
│ │赞 36 · 评论 12 · 回复     │ │  互动行
│ └────────────────────────┘ │
│ [广告位2] 帖子流内嵌横条      │
└────────────────────────────┘
发帖入口：页面右上角"发帖"按钮（或 FAB，与需求页区分：文案"发帖"）
```

**话题字典（初始，可运营扩展）：** 规培心得 / 病例讨论 / 求助提问 / 经验分享 / 考研考博 / 招聘信息 / 闲聊灌水

**合规双闸门：**
1. 发帖/评论/回复提交前 `msgSecCheck` 文本检测，违禁（政治敏感/黄赌毒/暴力等）直接拦截并提示；
2. 图片 `imgSecCheck`；举报入口全量覆盖，举报成立下架 + 账号处置；
3. 运营侧敏感词黑名单二次过滤（字典可配置）。

## 5. 广告位（D14）

| 位置 | 形态 | 定向字段 |
|---|---|---|
| 需求流第 2 条 | 原生卡片（浅金底 + "广告"角标） | province / city / hospital_id |
| 留言板帖子流 | 内嵌横条（第 4 条后） | 同上 |

```js
// ads 集合结构（Pilot 期不投放，仅预留）
{
  _id, title, image_fileID, jump_type(none/web/page), jump_value,
  province, city, hospital_id,     // 地域定向：null=全国
  slot: 'dealing_feed_1' | 'board_feed_1',
  status: active/disabled,
  start_at, end_at, priority, created_at
}
```

投放逻辑（服务端注入信息流）：按用户浏览地域（browsingHospital 所属省市）匹配 `ads`，插到信息流固定位；无匹配不展示。上线广告前需补充：广告主资质、流量主开通（微信流量主需小程序累计独立访客达标）、广告内容审核。

## 7. 发帖与评论交互（v1.1 增补，决策 D15-D17）

### 决策记录

| # | 决策 | 结论 |
|---|---|---|
| D15 | 发帖身份 | **实名 + 匿名可选**：实名显示"昵称·医院"；匿名显示"匿名用户"。posts 存 `is_anonymous`，服务端始终记录真实 uid（追责链路保留） |
| D16 | 评论层级 | **两级**：一级评论平铺 + 二级回复（"回复 @xx："前缀），微信评论区同款 |
| D17 | 图片审核 | **自动审核**：imgSecCheck 全量先审后发，Pilot 期不设人工复审；举报下架兜底 |

### 发帖页结构

```
话题胶囊单选（必选，7 类初始字典）
→ 标题（30 字内，必填）
→ 正文（1000 字内，必填；病例话题强制脱敏提示）
→ 图片 0-3 张（imgSecCheck，Pilot 上限 3 张）
→ 身份切换：实名（昵称·医院）/ 匿名（默认实名）
→ 右上角"发布"按钮；提交即检测，违禁拦截红条提示常驻表单底部
```

### 帖子详情页结构

```
帖子卡：头像/昵称（或"匿名用户"）· 医院 · 话题 · 时间 · 正文 · 图片九宫格
互动行：♡ 点赞（乐观更新，再点取消）· 举报
评论区（两级）：
  一级评论：平铺列表（头像/昵称/时间/内容/回复/删除）
  二级回复：挂在一级评论下，「回复 @xx：」前缀
底部固定输入框：评论或回复（回复时带 @目标），发送前 msgSecCheck
删除：仅自己的帖子/评论可删，确认后逻辑删除（deleted_at）
```

### 数据模型增补

```
posts: { _id, topic, title, content, images[fileID], author_uid,
         author_snapshot{nickname, hospitalName}, is_anonymous,
         province, city, like_count, comment_count, status(active/deleted), created_at }
comments: { _id, post_id, parent_id(一级为null), reply_to_uid, reply_to_name,
            author_uid, author_snapshot, is_anonymous, content,
            status(active/deleted), created_at }
post_likes: { _id, post_id, uid, created_at }  // 唯一索引 post_id+uid，点赞/取消
```
