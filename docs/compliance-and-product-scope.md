# 前期调研与决策记录（2026-08-25）

本文档记录开发启动前的调研结论与范围决策，作为后续设计的依据。结论以提审时微信官方最新文档为准。

## 一、产品定位（验证期）

- **目标用户**：医学生。
- **核心场景**：值班调班换班、病例指导互助。
- **验证期范围**：只做商品/需求展示 + 意向沟通（留言），**不做资金托管、不接支付**。目的在于验证供需，避免在合规资质到位前投入交易系统。
- **首版板块**：
  - 换班帖：科室、班次日期、换入/换出方向、说明。
  - 病例求助帖：科室、病例摘要、求助问题。
- **项目名**：MedWorkExchange（目录名 `MedWorkExchange`，技术产物统一小写 `medwork-exchange` 风格）。

## 二、合规红线：资金托管与"二清"

原始需求包含担保交易（买家付款 → 暂存 → 双方确认 → 打给卖家）。调研结论：

- 平台用自己的商户号/银行账户**代收买家款项再转付卖家**，属于"二次清算"（二清）。按央行《非金融机构支付服务管理办法》，无《支付业务许可证》做资金托管是**无证经营支付业务，明确违法**，不是灰色地带。
- 结论：平台代码中**任何路径都不得设计为"平台收款再转付"**，包括手动转账兜底。

## 三、正式期（若交易化）的合规路径

| 事项 | 要求 |
|---|---|
| 主体 | 企业（个人主体不能做电商类目、不能开微信支付） |
| 小程序类目 | 「电商平台」类目通常需《增值电信业务经营许可证》（EDI，在线数据处理与交易处理业务） |
| 担保交易实现 | 二选一：微信支付**分账 API**（支付后资金冻结在待结算账户，确认后解冻/分账给卖家）；或**电商收付通**（含二级商户进件、担保交易、分账、售后，闲鱼类平台标准方案） |
| 时间瓶颈 | EDI 办理周期约 1–3 个月，决定交易化时间线，若确定要走需尽早启动 |

关键点：两条路径下资金全程停留在微信支付体系内，平台只发起指令、不碰钱。

## 四、小程序主体与类目要求（验证期 vs 正式期）

- **验证期（信息展示 + 沟通）**：不涉及交易，主体门槛大幅降低，个人主体也有机会走「工具」/「社区」类目；使用微信云开发可**免自备服务器、免域名备案**。
- **正式期（交易化）**：见上表，需企业 + EDI + 电商收付通/分账。

## 五、UGC 内容安全（提审硬要求，验证期即需实现）

- 卖方/发帖内容属用户生成内容，需接入微信内容安全接口：文本 `msgSecCheck`、图片 `imgSecCheck`，违禁内容自动拦截。
- 需具备举报入口与内容下架机制（电商法对平台治理义务的要求；验证期弱化为基本举报/隐藏能力即可，但架构上预留）。
- 特殊品类（食品、图书、医疗器械等）有额外资质要求；换班/病例求助场景不涉及。

## 六、技术选型记录

- **小程序端**：原生开发（WXML/WXSS/JS）。理由：验证期只有微信一个端，无跨端需求，原生无转译层、坑最少。
- **后端**：微信云开发（云函数 + 云数据库 + 存储）。理由：免服务器、免域名备案、与微信登录/内容安全 API 集成最短。
- **账号体系**：`wx.login` 换 openid；收集手机号等敏感信息需用户授权 + 隐私政策配置。
